## 1. One-time setup — everyone, on any machine

### 1.1 Clone

```bash
cd /c                      # or wherever you keep projects
git clone https://github.com/Rishabhhcodes/ecg-paper.git
cd ecg-paper
```

The repository is public. Nothing to request, no access to arrange.

If you are going to push, do it on a branch — never on `main`:

```bash
git checkout -b my-branch-name
```

### 1.2 Python

**3.11 or newer.** Check:

```bash
python --version
```

### 1.3 Dependencies

```bash
pip install -r requirements.txt
```

If pip refuses with "externally managed environment", make a virtual
environment first. The activate command is the one place people lose ten
minutes:

| Shell | Command |
|---|---|
| **Git Bash on Windows** (`MINGW64` in the prompt) | `source .venv/Scripts/activate` |
| Windows CMD | `.venv\Scripts\activate.bat` |
| PowerShell | `.venv\Scripts\Activate.ps1` |
| macOS / Linux | `source .venv/bin/activate` |

```bash
python -m venv .venv
source .venv/Scripts/activate      # adjust per the table
pip install -r requirements.txt
```

Git Bash is the trap: the folder is `Scripts`, as on Windows, but the
slashes must be forward slashes, as on Linux. Backslashes give you
`bash: .venvScriptsactivate: command not found`.

Your prompt should now start with `(.venv)`.

### 1.4 What you do NOT need

- **Not the dataset.** You rebuild it; it is never sent around.
- **Not a GPU**, unless you are doing Stage 2B or Stage 4.
- **Not anyone's Drive.** Results move as zips, person to person.

## 2. How the pieces fit

```
download.py        PhysioNet  ──►  data/mitdb/
build_dataset.py              ──►  artifacts/ds1.npz, ds2.npz
verify_dataset.py                  21 checks, all must pass
                                        │
run_grid.py                           ──►  artifacts/preds*/        ← the real result
                                        │
rebuild_summary.py                    ──►  artifacts/grid_summary*.json   ← a view of it
seed_report.py                             the cross-seed analysis
stage3_decision.py                    ──►  artifacts/stage3/
stage4_final.py                       ──►  artifacts/stage4/    ← opens DS2, once
```

Two rules that fall out of this diagram:

**The prediction files are the result; the summaries are derived.** A
partial `run_grid.py` run rewrites the summary from scratch and can drop
rows from it without error. That happened once and cost us two published
claims. If a summary and the predictions ever disagree, the predictions
win, and `rebuild_summary.py` regenerates the summary from them.

**`artifacts/` and `data/` are gitignored and must stay that way.**
Nothing under them is ever committed. They are regenerated by the
commands above, and they move between people as zips.

## 3. Reproducing everything from scratch

Skip to section 4 if you are only doing the stage you were assigned.

### 3.1 Build the dataset — laptop, ~8 minutes

```bash
python src/download.py          # ~90 MB from PhysioNet, once
python src/build_dataset.py     # writes artifacts/ds1.npz, ds2.npz
python src/verify_dataset.py    # 21 checks — all must pass
```

Expected:

```
DS1  50,977 beats / 22 patients   N 45,824  S 943  V 3,788  F 414  Q 8
DS2  49,668 beats / 22 patients
```

Those totals are 44 below the published figures, which is exactly
accounted for: the first and last beat of each record are dropped because
RR features need a previous and a next beat, and 22 records × 2 = 44.

**If any of the 21 checks fails, stop.** Everything downstream is
meaningless on a bad dataset.

### 3.2 The grid, part A — laptop CPU, 30–90 minutes

```bash
python src/run_grid.py --models lr xgb
```

16 configurations. No GPU, no `torch` needed — the CNN import inside
`run_grid.py` is lazy.

### 3.3 The grid, part B — Colab GPU, ~1 hour

Needs a GPU, so it goes to Colab. Use
`notebooks/Stage2B_CNN_Rerun_Colab.ipynb`, which uploads the files it
needs directly into the session.

```bash
python src/run_grid.py --models cnn        # inside the notebook
```

10 more configurations. Results come back as a zip and unzip into
`artifacts/`.

### 3.4 The multi-seed repeat — Colab GPU, ~3.5 hours

```bash
python src/run_grid.py --models cnn --seed 1
python src/run_grid.py --models cnn --seed 2
python src/run_grid.py --models cnn --seed 3
python src/run_grid.py --models cnn --seed 4
```

Each seed writes to its own `artifacts/preds_seed{n}/`. This is what
produces the noise floor, and without it no close comparison in the paper
can be made at all.

### 3.5 Rebuild and check the summaries — laptop, seconds

```bash
python src/rebuild_summary.py           # dry run — says what is missing
python src/rebuild_summary.py --write   # regenerate from the predictions
python src/verify_summary.py            # every row against the .npz files
```

Always do this after any partial grid run. `verify_summary.py` must say
`0 stale`.

### 3.6 The analysis — laptop, seconds

```bash
python src/seed_report.py
```

Prints the per-configuration means, the noise floor, the 26-row RR
ablation, and which close comparisons can be ranked. If it warns that a
configuration is missing a seed, go back to 3.5.

### 3.7 Stage 3 — laptop, under a minute

```bash
python src/stage3_decision.py
```

No GPU and no dataset — it reads the saved predictions. Writes three
figures and a JSON to `artifacts/stage3/`.

## 4. Stage 4 — the one that is next

**Read this even if you are not the one running it.**

DS2 is twenty-two patients sealed since Stage 1. No model choice, loss
function or threshold in this project was selected using them. That is
what makes the Stage 4 number an estimate of generalisation rather than a
figure tuned toward.

**It runs once.** The first successful run writes
`artifacts/stage4/RECEIPT.json`; every later run is refused unless given
a written reason, which is appended to that receipt.

### 4.1 Who needs what

| Person | Sends | Gets back |
|---|---|---|
| Rishabh | `Stage4_DS2_Colab.ipynb`, optionally `stage4_preds.zip` | `stage4_results.zip` + the full text of the run |
| The runner | nothing | — |

The runner is sent no dataset. The notebook clones the public repo and
rebuilds MIT-BIH itself.

### 4.2 Rishabh, on the laptop — optional, 1 minute

```bash
cd /c/ecg-paper
python make_stage4_zip.py
```

Writes `stage4_preds.zip`, 50 files, about 10 MB. This is **optional** —
it adds one secondary result (whether a DS1-fitted temperature still
calibrates on unseen patients). Stage 4 runs without it and says so. Do
not delay the evaluation for this.

The packer refuses to build an incomplete zip, because a temperature
fitted on fewer folds than it reports is worse than no temperature.

### 4.3 The runner, in Colab — ~45 minutes

1. Open `Stage4_DS2_Colab.ipynb` in Colab.
2. **Runtime → Change runtime type → T4 GPU → Save.** Do this first.
3. **Runtime → Run all.**
4. At cell 5, upload `stage4_preds.zip` or dismiss the picker.
5. Wait. Cell 6 is the long one, about 25 minutes.

Full detail is in `STAGE4_INSTRUCTIONS.md`, which goes to the runner
along with the notebook.

### 4.4 Before Stage 4 can run at all

`src/stage4_final.py` and the updated `src/train_cnn.py` have to be on
`main`, because the notebook clones the repo. Section 6.

## 7. When something goes wrong

| Message | Cause | Fix |
|---|---|---|
| `bash: .venvScriptsactivate: command not found` | backslashes in Git Bash | `source .venv/Scripts/activate` |
| `ModuleNotFoundError: config` | run from the wrong directory | `cd` to the repo root; always run as `python src/<script>.py` |
| `ModuleNotFoundError: matplotlib` | see 6.2 | `pip install matplotlib` |
| `No GPU` in a notebook | runtime not set | Runtime → Change runtime type → T4 GPU → Save → Run all |
| `folds.json is missing` | incomplete clone | pull `main`. **Do not run `make_folds.py`** — a different scikit-learn produces a different split, which is the exact problem that file prevents |
| `cached prediction does not match current split` | predictions from a different dataset or a smoke test | delete the offending files under `artifacts/preds*/` and re-run |
| `*** N configuration(s) are missing a seed` | a partial grid run clobbered the summary | `python src/rebuild_summary.py --write` |
| `REFUSED — DS2 has already been opened` | exactly that | tell the team. **Do not pass `--reason` to get around it** |
| any `AssertionError` | a guard fired deliberately | send the whole message, do not retry |

### Numbers that mean something is wrong

| Sign | What it means |
|---|---|
| macro-F1 above **0.85** anywhere | almost certainly a leak. Nothing here reaches that honestly |
| a CNN seed finishing in far under 40 minutes | folds were skipped that should not have been |
| Stage 3's 0% rejection row not matching Stage 2 | the two are not computing the same thing — this is checked automatically and will assert |
| Class S F1 of exactly 0.000 | the model never predicted the class; check the strategy actually applied, in the `meta` field |

## 8. Rules that are not negotiable

1. **DS2 is opened once.** Everything in Stages 1–3 was decided without
   it. A test score you may re-run until it improves is not a test score.
2. **`src/folds.json` is never regenerated.** It is the protocol.
   `StratifiedGroupKFold` is deterministic within one scikit-learn
   version and not across versions — 1.6.1 and 1.9.1 split the same 22
   patients differently from the same seed, and half the grid was
   silently not comparable with the other half.
3. **Nothing under `artifacts/` or `data/` is ever committed.**
4. **Each person commits their own contribution**, on their own branch,
   through a pull request. The history is part of the record of who did
   what.
5. **A result that is too good is investigated, not celebrated.**
